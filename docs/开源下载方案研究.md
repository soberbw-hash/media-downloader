# 四类视频「一个链接就下」：开源方案调研 + 我们落地了什么

写于 2026-11-26。目的：把抖音 / 小红书 / B站 / 网盘四个方向的开源项目摸一遍，
挑出能直接用的手法，落到本软件里。**结论先给：抖音、B站、网盘已经免登录可用；
小红书的免登录这次真正打通了（之前是我们自己解析错了位置）。**

---

## 1. 抖音

| 项目 | 量级 | 核心手法 |
|---|---|---|
| Evil0ctal/Douyin_TikTok_Download_API | ~22k★ | `X-Bogus` / `A_Bogus` 签名请求 web detail 接口 + 自维护身份池（cookie 池），FastAPI 自托管 |
| JoeanAmier/TikTokDownloader | ~17k★ | 扫码登录写 cookie，按账号批量采；支持评论、直播 |
| Johnserf-Seed/TikTokDownload | ~8.9k★ | 早期逆向，`a_bogus` 参数复现 |
| erma0/douyin | ~1.6k★ | 单视频直解，代码最短，适合读思路 |

**共同点**：真正稳的是「签名 + 有效 cookie（ttwid/msToken）」；纯免登录靠的是**分享页 SSR**。

**我们现在的做法**（`core.py` → `_douyin_ttwid` / `_douyin_share_item`）：
先向 `ttwid.bytedance.com` 注册拿游客 `ttwid`，再请求
`https://www.iesdouyin.com/share/{video|note}/<id>/`，从页面里的 `_ROUTER_DATA`
取 `item_list[0]`，播放地址用 `play_addr` 并把 `/playwm/` 换成 `/play/`（去水印）。
**实测**（今天，两条真链）：`v.douyin.com/mNgoRM3agoU`、`v.douyin.com/LfDrZ5fmFLk`
都能拿到标题、作者、时长和 1080p 直链，全程没登录。

**可借鉴但暂不做**：`a_bogus` 签名（能走 detail 接口拿更全的画质列表），工程量在
JS 逆向 + 频繁变动，收益是「极少数被风控的链接」。现在这条 SSR 路子已覆盖日常。

## 2. 小红书（这次的主战场）

| 项目 | 手法 |
|---|---|
| JoeanAmier/XHS-Downloader | 免 cookie 可下但只有低码率；配 cookie 解锁高清。链接必须带 `xsec_token` |
| zhoulujue/xiaohongshu-post-analyzer | **不开浏览器、不登录**：直接读笔记页 SSR 的 `window.__INITIAL_STATE__`，强调 token 必需、state 常被截断、`xhslink.cn` 返回的是 HTML 跳转而不是 302 |
| Spider_XHS | 复现 `x-s` / `x-t` 签名调 `/api/sns/web/v1/feed`，能力最全，维护成本最高 |

**关键事实（今天逐条实测过）**

1. `xsec_token` 是通行证：`/explore/<id>`、`/discovery/item/<id>` 不带 token 一律 404 或登录页。
2. **桌面 UA** 打开 App 分享链 → 被踢到 `/login?redirectPath=<原链接>`，
   **token 就藏在 redirectPath 里**；旧代码只读最终 URL 的 query，token 直接丢了。
3. **手机 UA** 打开同一条分享链 → 直接落到 `/discovery/item/...?...xsec_source=app_share`，
   页面 63KB，正文在 `__INITIAL_STATE__.noteData.data.noteData`（不是 `noteDetailMap`）。
   旧代码只认 `noteDetailMap`，所以明明有内容却报「登录过期」。
4. `xsec_source` 不能删：同一个 token 去掉 `xsec_source` 后用 `/explore/` 打不开。
5. 连续请求会触发安全层（`300012 当前网络存在风险` / 滑块），**不要连刷**。

**我们改了什么**（`cn_sites.py`）

- `_xhs_url_parts()`：把 `redirectPath` 逐层拆开还原真实链接，token 用正则原文取
  （`parse_qs` 会把 token 里的 `+` 当空格，签名就废了）。
- `_xhs_note_paths()`：`noteDetailMap` 和 `noteData.data.noteData` **两套结构都认**。
- 请求顺序改为「原样分享链 + 手机 UA」优先，其次才拼 discovery / explore；
  **匿名先试，cookie 后补**（以前带着过期 cookie 先试，页面退化成登录墙）。
- 加 `_xhs_risk()`：识别 300012 / 滑块页，文案直说「换网络，别去登录」。
- 加 `_xhs_note_from_regex()`：state 被截断时用正则从残页里捞 `masterUrl` / `originVideoKey`。
- 图片取 `!h5_1080jpg` 那版（实测去掉后缀会 403），preload 那批只在 imageList 缺失时兜底，避免重复下载。
- 缺 token 直接给准确指引：「回 App 里分享 → 复制链接」，不再含糊报登录。

**实测结果**：`https://xhslink.cn/o/9UWBdRy7GUA`（图文笔记）免登录下载成功，
6 张 1080 图全落盘（347KB / 356KB / 429KB / 307KB / 379KB / 188KB）。
视频笔记的结构同一套（`noteData.data.noteData.video.media.stream`），已有单测覆盖。

**没跟的技术**：`x-s` 签名。收益是「不依赖 token」，但它需要持续对抗风控更新，
且我们这台机器当前网络已被判风险（300012），签名也救不了 IP。

## 3. B站

- **yt-dlp**（我们已经在用，运行时 2026.10.26）：B站 extractor 齐全，
  自动做 `wbi` 签名、支持分P / 番剧 / 弹幕。
- **bilibili-API-collect**：社区维护的接口文档，查 `x/player/playurl` 的参数最省事。
- 其他：you-get（老牌）、biliup（偏投稿）。

**实测**（无 cookie，`BV1NMW86XEdA`）：可下 **1080P**（avc1/hevc/av1 三路都有），
只有 **4K 超清 / 1080P 高码率**提示需要大会员。也就是说日常「一个链接就下」已经成立。

**可借鉴**：如果以后用户想要更高码率，走「登录一次 → cookie 交给 yt-dlp」，
由 yt-dlp 自己处理，不需要我们写解析。

## 4. 网盘（百度 / 夸克 / 蓝奏）

| 项目 | 手法 |
|---|---|
| BaiduPCS-Go | 模拟客户端协议，支持秒传、离线，重量级 |
| alist | 多网盘聚合挂载成 WebDAV，思路是「挂载」而不是「下载单文件」 |
| baidupcs-web | 上面的 Web 壳 |

我们没引这些（都要账号 + 服务端），而是自己适配了分享页：
`disk-share-v2` 的 `<script id="locals-data">` + `/share/list`（带 `shorturl`/`root`/`view_mode`）
+ `/share/tplconfig` 取 `sign`，**匿名、带提取码**即可列目录下载（11-26 已修好并实测）。

## 5. 差距清单（按性价比排序）

| 想做的事 | 值不值 | 说明 |
|---|---|---|
| 小红书 `x-s` 签名 | 暂不做 | 收益小、维护重，且当前网络被判风险，签名也绕不过 IP 层 |
| 抖音 `a_bogus` / detail 接口 | 观察 | 现在 SSR 路子覆盖得够，等真出现大面积失败再上 |
| B站登录后高码率 | 可做 | 交给 yt-dlp，只需把 cookie 传下去（现在已有 cookie 通道） |
| 多线程分片下载 / 断点续传 | 可做 | 大文件体感提升明显，跟平台无关 |
| 快手 | 待验证 | 代码里是 `experimental`，需要真链验证一轮 |

---

## 6. 一句话总结

「一个链接就能下」在抖音、B站、网盘上已经是现实；小红书这次把**我们自己的解析错误**
修掉了（token 丢在 redirectPath、正文在 noteData 而不是 noteDetailMap、匿名优先），
现在分享链接贴进来就能下。剩下真正会挡路的不是技术，是平台对**网络/IP**的风控
（300012）：那种情况换网络比重构代码有用。
